The Android programs merging the paired databases, each result read back.

A block is one file as `Kpg.cs` read it with KeePassLib 2.61.1, less the work directory in front of
its path. Its first line is the summary: the file, the KDBX version, then each of the plugin's keys
as label:value/time. A value is `=` where C and P hold the same and this file holds it, `C` or `P`
for that copy's, and the whole item is `label:-` where the key is absent. A time is `=`, `C` or `P`
the same way and `none` where the key has no modification time. `G:` and `E1:` are the rule on that
group and that entry: `C`, `P`, or `-` for none. `E2@H(prev)` is an entry in H whose previous parent
group is still recorded. Under it: the bytes, the KDF, each key with its value cut at 40 characters
and its time after `@`, then every group and entry with its modification time, its previous parent
and its custom data.

A cell is named for what was done. `PC` is P open in the program and C arriving, `CP` the reverse,
and a trailing `s` is a source whose `SettingsChanged` is the later. In Keepass2Android the source
is written over the open file, an entry `droid-merge` is added and saved, and the prompt that raises
is answered "Yes, merge". In KeePassDX `ext` is the same replacement answered with "Merge data",
with no entry added; `from` is "Merge from ..." with the source in a file of its own, read back
afterwards as the `-src` file; and `keep` is the replacement with no merge asked for, an entry added
and saved. KeePassDX 3.2.0 writes nothing at "Merge data", so "Save data" follows it there.

Each program has the summary line of every run, then run 1 of each cell in full, then how the other
runs of that cell differ from it once the path, the bytes and the time taken to open are set aside.
